# F-079 立即显示任务与慢速参考图上传修复

用户明确要求：点击提交立即显示任务已提交，参考图在后台上传，用户只关心任务最终成功或失败；同时检查服务器能否提高上传带宽。

## 设计

- 校验本地参数后，先创建并选中具有固定 generationId 的任务卡，显示“任务已提交”，随后异步上传参考图并提交生成。上传细节不出现在正常用户流程。
- 提交快照冻结模型、参数、Key、参考图顺序；Key和待上传文件仅在内存，不进入历史记录。
- 尚在上传的本地任务不得被服务器 missingIds 提前判失败，也不得作为缺参考图的文生图重试。上传失败保留任务卡并允许在当前页面重试，继续使用原ID及原快照。
- 生成结果及失败在原卡片更新；刷新时对尚未送达服务器的本地任务明确显示中断状态，不能永久挂起或自动调用生成服务。
- 仅参考图请求体的读取预算从15秒改为120秒；JSON仍为15秒；单图4MiB、同源、owner和限流边界不变。
- 线上Caddy、Docker和tc未设置带宽限速；不虚构提速参数，不改服务器供应商套餐。

## 实施与验证

- [x] 根因证据：线上 uploads 408约15秒，对应Caddy断连502；本机922428B限速上传收到连接重置。
- [x] 上传预算TDD：20秒上传成功、120秒截止取消、JSON仍15秒截止。
- [x] 前端TDD：上传未返回即显示任务；四图顺序、失败重试、快照隔离、missingIds和刷新恢复。
- [x] 浏览器端到端：暂停上传响应，验证已提交卡片；释放后原卡完成；失败原卡可重试。
- [x] typecheck、全量单测、E2E、build、产物密钥检查、audit及独立审查。
- [ ] 部署与同图同限速线上复验，记录交接并清理临时探针。
