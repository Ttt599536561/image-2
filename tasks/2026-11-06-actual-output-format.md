# F-084：GIF 请求保留实际返回的图片

用户希望即便要求 GIF，也能看到上游实际返回的 PNG、JPEG 或 WebP 原图，用结果判断渠道支持情况。

- 故障依据：北京时间 07:50:47 的任务 `809aa079-8de8-4437-9386-cb56edfb2cb3` 已向正式网关请求 GIF；网关请求 `1c0fea68-8d62-44d4-b204-bcb99ce7843e` 返回 HTTP 200，记录 1 张图片。旧工作台在保存前抛出特定的 GIF 不匹配错误。这个分支意味着选中的是已识别的非 GIF 图片或单帧 GIF，但旧任务未保存字节或具体 MIME；不能追溯断定它是 PNG。同步网关账单中没有原图、帧数或可用于取回文件的异步任务号。
- 若同一结果同时含 URL 与非空 `b64_json`，采用所请求的内联原件；只有缺少内联表示时才走已有的安全下载路径。不访问额外链接，不重复生成，不改变多结果条目顺序。
- 请求 GIF 时按已验证文件签名保存 PNG/JPEG/WebP 的原字节、MIME 和后缀，结果/历史标明请求与实际格式，下载保持原文件。GIF 动画仍检查结构；单帧 GIF 返回明确提示，未知或损坏的头部仍拒绝。沿用既有体积与出站规则。
- 实际类型由已存的 `images.content_type` 投影到受限的成功状态，无需迁移。原始任务和创作面板仍为 GIF，只有主动点“以图编辑（PNG）”才切换该编辑草稿。
- 端到端以一次真实浏览器提交、隔离 PG、夹具上游回 PNG 验证下载及历史，无付费生成。改动只对新收到的结果生效，不能恢复先前已丢弃的字节。
