# tasks/ 目录使用规范

> 本目录存放"任务卡"：每个新需求/较大改动对应一个文件。
> 出处：Anthropic《Claude Code Best Practices》——spec 要自包含
> （点名文件、声明范围外、以端到端验证收尾）；《Harness Design》——
> 动手前先谈妥"合同"。

## 什么时候建任务卡

- ✅ 新功能、涉及多个文件的改动、涉及钱/安全的改动 → **必须先建卡**
- ❌ 改 typo、调样式、一行小修复 → 不必建卡，直接开干

## 流程

1. 复制 `TEMPLATE.md`，命名为 `YYYY-MM-DD-<功能名>.md`
2. 人描述需求，AI 填写其余各节，双方确认（这就是"合同"）
3. 干活会话围绕任务卡执行；验收后把状态改为"已验收"
4. AI 把新功能条目追加到 `docs/FEATURES.md`，编号顺延
